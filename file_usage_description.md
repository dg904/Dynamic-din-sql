# File Usage Description

This document outlines the purpose and functionality of every file and directory in the final implementation of the Extended DIN-SQL project.

## Core Implementation Files

### `extended_DIN_SQL.py` (or `extended_DIN_SQL_new.py`)
**Purpose:** The central, unified pipeline script for the project. 
**Usage:** Orchestrates the entire workflow from end-to-end. It uses `SentenceTransformers` to embed incoming natural language queries, retrieves the most similar examples from the `FAISS` vector store, constructs the few-shot prompt, and queries the **NVIDIA NIM API** to generate the SQL query. It handles executing the SQL output against the database to calculate the final performance metrics (Execution Accuracy and Exact Match).

### `requirements.txt`
**Purpose:** Defines all Python dependencies.
**Usage:** Used to recreate the environment on a new machine. Includes mandatory dependencies like `faiss-cpu`, `sentence-transformers`, `numpy`, and `requests`.

### `.env`
**Purpose:** Environment configuration file.
**Usage:** Securely stores the `NVIDIA_API_KEY` to avoid hardcoding sensitive tokens directly into the Python scripts.

---

## The `/files` Directory (Helper Modules)

### `files/sql_schema_linker.py`
**Purpose:** Schema linking utility.
**Usage:** Parses the Spider dataset's `tables.json` to extract and format table names, column names, and foreign key constraints. It injects this necessary context into the LLM prompt to inform the model of the available database structure.

### `files/evaluator.py`
**Purpose:** Evaluation metrics engine.
**Usage:** Contains the logic to compute **Execution Accuracy (EX)** (whether the generated query returns the same data as the gold standard query) and **Exact Match (EM)** (whether the SQL structural logic perfectly aligns). It assigns queries to difficulty tiers (Easy, Medium, Hard, Extra) for segmented reporting.

### `files/local_benchmark.py`
**Purpose:** Offline sandbox and validation tool.
**Usage:** Runs a small-scale, offline version of the benchmark using built-in mock databases (`school` and `store`). Used to validate that the pipeline logic and NVIDIA API connection are working perfectly without needing the entire multi-gigabyte Spider dataset present.

---

## Datasets and Data Stores

### `/spider` Directory
**Purpose:** The main evaluation dataset.
**Usage:** Contains `train_spider.json` (used as the semantic knowledge base for dynamic retrieval), `dev.json` (the validation questions to evaluate the model on), `tables.json` (the raw schema metadata), and the `/database` folder containing the actual SQLite databases required to test Execution Accuracy.

### `/vector_store` Directory
**Purpose:** Persistent cache for semantic search.
**Usage:** Contains `spider_faiss.index` and `spider_mapping.pkl`. Instead of recalculating embeddings for the 7,000+ Spider training questions on every single run, the script saves the mathematical vector representations here. The script loads this directory to perform rapid $O(1)$ similarity search during dynamic retrieval.

---

## Outputs and Logs

### `/results` Directory
**Purpose:** Auto-generated output tracking.
**Usage:** Overwritten during every pipeline execution. It stores:
- `extended_din_sql_results.json`: Raw telemetry, latency speeds, and success rates.
- `extended_din_sql_results.md`: A human-readable markdown summary of the benchmark run.
- `extended_static_predictions.sql` & `extended_dynamic_predictions.sql`: The raw SQL lines generated by the LLM, used by evaluators to inspect model outputs.
